# QuickPages AI Documentation

# 00-rules.md

## Purpose

This document defines the non-negotiable rules that every AI agent (Windsurf, Cursor, Claude Code, GitHub Copilot, or similar) must follow while designing and developing the QuickPages website.

These rules have higher priority than any other document inside `/docs`.

If another document conflicts with these rules, this file always takes precedence.

---

# Project Goal

QuickPages is not a personal portfolio.

QuickPages is a creative web studio.

The website itself must be the best demonstration of the quality that the studio can deliver to future clients.

Every design decision, animation, interaction and component must reinforce this idea.

The goal is not to impress developers.

The goal is to earn the trust of business owners.

---

# Design Philosophy

Everything must feel intentional.

Nothing should exist only because it looks good.

Every element must have a purpose.

Every animation must improve the experience.

Every section must tell part of the story.

The website should feel timeless.

Never trendy.

Never overloaded.

Never generic.

---

# Identity

QuickPages represents a boutique creative studio.

It should communicate:

- Precision
- Professionalism
- Simplicity
- Confidence
- Attention to detail
- Modern development
- Premium quality

It should never communicate:

- Corporate
- Startup cliché
- Futuristic
- Gamer
- Web3
- AI generated
- Tailwind template

---

# User Perception

When someone visits QuickPages they should think:

"If this is their own website, I want them to build mine."

Everything should work toward that emotional response.

---

# Experience Principles

The website should feel calm.

Elegant.

Editorial.

Minimal.

Fast.

Purposeful.

Never noisy.

Never overwhelming.

Never childish.

---

# Core Principles

Prioritize:

Clarity over decoration.

Quality over quantity.

Whitespace over crowded layouts.

Typography over illustrations.

Content over effects.

Experience over animations.

Performance over complexity.

Consistency over experimentation.

---

# Forbidden Elements

Never use:

Huge glassmorphism effects.

Heavy gradients.

Neon colors.

Glow effects.

Particle backgrounds.

Animated backgrounds.

Infinite decorative animations.

3D objects without purpose.

Overly rounded interfaces.

Complex dashboards.

Templates.

Cookie-cutter sections.

Duplicated layouts.

---

# Components

Every component must feel custom.

Avoid generic UI.

Avoid obvious Tailwind patterns.

Avoid repetitive cards.

Each section should introduce something visually different while remaining consistent with the design system.

---

# Navigation

Navigation must always feel effortless.

Scrolling should naturally guide the visitor.

The navigation should never distract.

Users should always understand where they are.

---

# Animations

Animations are tools.

Not decorations.

Every animation must answer one question:

"What purpose does this movement serve?"

If there is no clear answer,

remove it.

---

# Motion Rules

Movement should be:

Natural.

Slow enough to feel premium.

Fast enough to avoid frustration.

Consistent.

Elegant.

Never exaggerated.

Never playful.

Never distracting.

---

# Typography

Typography is the main visual element.

Large titles.

Comfortable reading width.

Generous spacing.

Excellent hierarchy.

Avoid excessive font weights.

Avoid decorative fonts.

---

# Images

Images should support the content.

Never dominate it.

Avoid stock photography whenever possible.

Prioritize:

Project screenshots.

Device mockups.

Minimal compositions.

Clean backgrounds.

---

# Color Usage

The interface should remain mostly neutral.

Accent colors should be used sparingly.

Users should naturally understand interactive elements through subtle contrast.

Color should guide.

Not decorate.

---

# White Space

Whitespace is part of the design.

Never try to fill empty areas.

Empty space creates rhythm.

Rhythm creates elegance.

---

# Copywriting

Do not exaggerate.

Do not oversell.

Avoid marketing clichés.

Speak with confidence.

Be clear.

Be concise.

Be human.

Never sound robotic.

---

# Technical Direction

Code quality is part of the product.

Components must be reusable.

Files must remain organized.

Avoid duplicated logic.

Avoid unnecessary dependencies.

Avoid large components.

Prefer composition.

---

# Accessibility

Accessibility is mandatory.

Never sacrifice usability for aesthetics.

Keyboard navigation must always work.

Focus states must remain visible.

Semantic HTML is required.

Proper heading hierarchy is required.

Alt text is required.

Contrast ratios must remain accessible.

---

# Performance

Performance is part of the experience.

Animations should never reduce responsiveness.

Every optimization matters.

Images should be optimized.

Fonts should be optimized.

JavaScript should remain minimal.

---

# Responsive Design

Responsive design is not adaptation.

Each viewport should feel intentionally designed.

Desktop.

Tablet.

Mobile.

Every version must provide an excellent experience.

---

# SEO

Every page must include proper metadata.

Semantic structure.

Meaningful headings.

Open Graph.

Twitter metadata.

Structured data whenever appropriate.

Performance should always support SEO.

---

# Project Structure

Maintain a clean architecture.

Each folder should have a clear purpose.

Never mix unrelated responsibilities.

Keep components small.

Keep logic isolated.

Prefer readability over cleverness.

---

# Quality Control Checklist

Before considering any feature complete, verify:

✓ Does it reinforce the QuickPages identity?

✓ Does it improve the user experience?

✓ Is it visually consistent?

✓ Is it technically clean?

✓ Is it accessible?

✓ Is it responsive?

✓ Is it performant?

✓ Is it necessary?

If any answer is "No", revise the implementation.

---

# Decision Priority

When making decisions always follow this order:

1. User Experience

2. Brand Identity

3. Design System

4. Accessibility

5. Performance

6. SEO

7. Code Quality

8. Visual Details

Never prioritize aesthetics over usability.

---

# AI Behavior

When generating new components:

Do not invent random styles.

Do not switch visual languages.

Do not introduce unnecessary colors.

Do not change typography.

Do not redesign existing components without reason.

Always respect the established design system.

---

# Final Objective

QuickPages should not feel like a portfolio.

It should feel like the website of a creative studio capable of designing exceptional digital experiences.

Every page, every interaction and every animation should naturally convince potential clients that QuickPages is the right choice for their next website.
